① 先做三步自检

遇到"打不开"时，先按顺序做完这三步，多数情况能直接定位原因。

第 1 步：确认加速是否真的在生效

打开命令提示符，输入下面的命令：

nslookup github.com

返回结果 说明
Address: 127.0.0.1 正常。DNS 已被本程序接管，加速正在工作。
Address: 20.205.243.166 之类的公网地址 未生效。程序没有以管理员身份加载驱动，请见下方「双击没有反应」。

第 2 步：确认后端进程还活着

打开任务管理器，切到「详细信息」，应当能看到两个进程：

  • FastGithub.UI.exe —— 托盘界面
  • fastgithub.exe —— 真正做加速的后端

界面在、后端不在，说明后端启动失败或被安全软件拦截，此时所有网站都不会被加速。

第 3 步：确认浏览器不是旧连接

浏览器会缓存 DNS 结果和 TLS 连接。程序刚启动或刚更新过 IP 时，旧连接仍指向失效的地址，表现为"能开但一直转圈"。请彻底退出浏览器再重新打开（只关标签页无效，需要关闭全部窗口）。

判断是不是本程序引起的问题：在托盘图标上右键 →「关闭应用」，然后重新执行第 1 步。 此时 nslookup github.com 会返回真实公网 IP。如果这时 GitHub 能正常打开，说明问题出在加速链路（继续往下看）； 如果这时照样打不开，问题在本机网络或运营商，与本程序无关。

② 常见问题

1. 浏览器提示"您的连接不是私密连接"

NET::ERR_CERT_AUTHORITY_INVALID　/　此网站出具的安全证书不是由受信任的证书颁发机构颁发的

原因是本程序的根证书没有被系统信任。程序会在启动时自动安装，但需要管理员权限，安装失败的常见情形：

  1. 以普通权限启动（没有出现 UAC 提示）→ 右键程序 →「以管理员身份运行」一次。
  2. 用 360、火绒、腾讯电脑管家等拦截了证书安装 → 临时关闭拦截后重启程序。
  3. 证书已安装但浏览器缓存了旧连接 → 彻底退出浏览器后重开。

手动确认证书是否已安装：按 Win + R，输入 certlm.msc，在「受信任的根证书颁发机构 → 证书」中查找 FastGithub。

2. Firefox 提示 SEC_ERROR_BAD_SIGNATURE

连接到 github.com 时发生错误。对等端的证书有一个无效的签名。

Firefox 使用独立的证书库，默认不读取 Windows 系统证书，需要打开企业根证书支持：

1地址栏输入 about:config 并回车

2搜索 security.enterprise_roots.enabled

3把它改为 true，然后重启 Firefox

3. git clone / pull / push 报证书错误

fatal: unable to access 'https://github.com/xxx.git/'
SSL certificate problem: unable to get local issuer certificate

git 在同一个终端里会复用已经建立的连接。改完设置后必须关掉当前的 cmd / PowerShell / Git Bash 窗口重新打开，否则用的还是旧连接。

如果重开仍然报错，说明 git 自带的证书链没有更新到系统根证书。临时绕过（仅建议临时使用，会降低安全性）：

git config --global http.sslverify false

关闭 sslverify 后 git 不再校验证书，理论上可被中间人窃听。确认验证通过后建议改回 git config --global http.sslverify true。

4. 打不开 GitHub，页面一直转圈最后超时

页面空白转圈，最后显示「无法访问此网站」ERR_CONNECTION_TIMED_OUT

这是候选 IP 失效的典型表现。GitHub 各地入口的可用性随时在变，程序会记住历史上可用的 IP，但失效后需要重新测速。按顺序尝试：

  1. 托盘图标右键 →「更新IP(&R)」，等提示"IP更新完成"。
  2. 关掉浏览器全部窗口再重新打开（清连接缓存）。
  3. 仍然不行，就在「设置」页查看「加速服务状态」，确认后端是"运行中"。

更新 IP 期间（约 10~30 秒）网络会短暂变慢，这是正在并发测速的正常现象，结束后恢复。

5. 提示"找不到任何可成功连接的IP"

找不到任何可成功连接的IP，已自动触发IP更新，请稍后重试 (github.com:443)

含义是：程序把这条域名的所有候选 IP 都试过了，没有一个能在超时内完成连接。此时它已经在后台自动触发一次 IP 更新，通常等十几秒后刷新页面就会恢复。

如果反复出现，说明当前网络的出口被整体阻断（例如公司内网限制了 443 出站，或运营商在特定时段干扰）。可以尝试切换网络（手机热点）对照确认。

6. 页面能打开，但头像、样式、图标加载不出来

GitHub 的页面由多个域名拼成：主页面来自 github.com，样式与脚本来自 github.githubassets.com，头像来自 avatars.githubusercontent.com。某一个域名的 IP 失效，就会出现"文字出来了、排版全乱"的现象。

处理方式和第 4 条一样：更新 IP 后重开浏览器。程序内置了这几个域名的独立候选池，正常更新一次即可补齐。

7. 双击没反应，或者提示需要管理员权限

加速依赖 WinDivert 驱动做数据包拦截，必须管理员权限才能加载。判断标准还是第 1 步的 nslookup：

  • 返回 127.0.0.1 → 驱动已加载，权限正常。
  • 返回公网 IP → 权限不足或驱动被拦截，右键「以管理员身份运行」。

如果每次开机自启后都失效，是因为 Windows 的开机启动项默认不带提权。解决办法：控制面板 →「任务计划程序」→ 新建任务，勾选「使用最高权限运行」，触发器设为「登录时」，操作指向 FastGithub.UI.exe。

8. 和其他代理 / VPN 软件冲突

本程序工作在数据包层，会直接接管 80 / 443 端口的连接。同时开启 Clash、v2ray、SSR 之类的代理工具，两者会争抢同一批连接，表现为时好时坏、随机超时。

建议只保留一个：要用本程序时先退出其他代理软件；本程序也不需要设置任何系统代理。

9. 会不会拖慢其他网站

不会。程序只对配置里列出的域名做重定向，其余网站的 DNS 与连接原样放行，不经过本地转发。

10. 怎么彻底退出

点击窗口右上角的 × 或最小化，都只是把它隐藏到托盘，加速仍在继续。要真正退出，在托盘图标上右键 →「关闭应用(&C)」。

③ 加速范围

默认覆盖 GitHub 相关的核心域名：

域名 用途
github.com主站、仓库页面
api.github.comAPI 调用、GitHub Desktop
gist.github.com代码片段
codeload.github.com源码压缩包下载
raw.githubusercontent.comraw 文件、Homebrew 等
avatars / camo / objects.githubusercontent.com头像、图片、附件
github.githubassets.com页面样式与脚本
github.ioGitHub Pages 站点

另外还内置了若干常见开发站点的规则（Google、Microsoft、npm 等），可在程序目录的 appsettings 文件夹里查看，按需增删，改完重启程序生效。

不覆盖的情况：直连 IP 的访问、非标准端口的服务、以及程序未列出的域名。这类情况本程序不会介入。

④ 工作原理

  • 不改 hosts 文件，不会在系统里留下需要手动清理的记录。
  • 不设置系统代理，所以不会影响不需要加速的程序，也不会让内网系统走错路由。
  • 通过 WinDivert 驱动在内核层拦截 DNS 查询与 TCP 连接，把命中规则域名的请求重新解析到一个实测可用的 IP。
  • 每个候选 IP 都要通过 TCP 连接与 TLS 握手两段校验才算"可用"，避免把只开放端口但拒绝握手的地址当成可用入口。
  • 已确认可用的 IP 会写进 ipaddresses.json，重启后立即复用，不必再从零测速。

⑤ 安全与隐私

为了做 TLS 转发，程序会在本机安装一张自签根证书。这张证书：

  • 只安装在本机，不会上传到任何服务器；
  • 仅用于本程序发起的连接，不参与其他软件；
  • 可以随时在 certlm.msc 中删除，删除后加速立即失效但系统不受影响。

程序不收集账号密码，不上报浏览记录。日志文件保存在程序目录的 logs 文件夹，按天分文件，只记录域名与连接结果，可随时删除。

⑥ 还原与卸载

三步可以完全还原到使用之前的状态：

  1. 托盘右键 →「关闭应用」。
  2. 按 Win + R 输入 certlm.msc，在「受信任的根证书颁发机构 → 证书」中删除 FastGithub。
  3. 删除程序目录即可。若开启过开机自启，请在「设置」页先关闭，或到任务管理器 →「启动」中禁用。
卸载后如果 GitHub 反而打不开，先执行 ipconfig /flushdns 清一下 DNS 缓存，再重开浏览器。

没找到对应的问题？把以下信息一起反馈，定位会快很多：

  • 托盘「设置」页里显示的运行状态与端口；
  • 具体打不开的网址，以及是"立刻报错"还是"转圈超时"；
  • 程序目录 logs 下当天的那份日志。
